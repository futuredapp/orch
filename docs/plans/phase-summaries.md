# Testing strategy restructure — phase summaries

## Phase 1

Phase 1 (parent unit **U1**) stands up the new `tests-new/` tree and the shared
scenario/driver DSL spine, plus the three foundations the rest of the migration
depends on. The DSL lets a behaviour be written once as a `scenario(meta, body)`
and run at multiple fidelities by *listing drivers*; the typed app surfaces make
an unsupported action a **compile error** (e.g. a `model`-only scenario cannot
call `rightPane`/`resize`). Only the `model` driver (no tmux, renders the real
steps-view via ink-testing-library and asserts the projected view-model) and the
`tmux-argv` category (plain `RealTmuxService` + `FakeProcessService` argv test)
are live; the five real-tmux/agent drivers are skip-stubs that land in U2/U3.
Two tracer tests prove the design end-to-end on real controller logic.

Three load-bearing foundations are now in place. **Typecheck gate (D11):**
`tests-new/` is in `tsconfig` `include`, so `tsc --noEmit` enforces the whole
typed-DSL contract — verified by introducing a deliberate type error and
confirming it goes red. Negative `@ts-expect-error` tests in `scenario.test-d.ts`
ride this gate. **Frozen baseline (D12):** `tests-new/_migration/baseline.json`
is a committed snapshot of every `tests/**` path (425 files, 2517 cases),
classified and with per-case identity, generated by a deterministic TS-AST script
that never imports test files. All later completeness accounting queries this
frozen artifact, not a live scan. **`_support/` infra home (D13):** `ink-frame`
and `type-assertions` moved there, the `@orch/test/*` alias was repointed to it,
and thin re-export shims were left at the old `tests/helpers/` paths so the still-
green old suite keeps resolving.

What matters for the next phase: the old `tests/` suite is **untouched** (no test
skipped) and still guards — only the two helpers moved (behind shims) and the
typecheck gate widened. The full old unit suite (1954 tests) and the new tree (19
tests) are green, and the new fast bucket (`bun run test:two-pane:fast`) boots no
tmux. The default `test`/`check` scripts still point at the old tree (they get
repointed in U14); U1 only added the `test:two-pane:{model,tmux-argv,fast}`
buckets. Two known background facts to carry forward: the shared tmux socket dir
already holds ~133 leaked `orch-*` sockets from the legacy real-tmux suite (the
flakiness root cause U2's drivers must fix), and the baseline must never be
regenerated against the mutating tree.
